## Verificación reproducible

Desde la raíz del producto:

```powershell
node packages/kairos-cli/tests/run.mjs
docker build -f packages/kairos-cli/Dockerfile.test -t kairos-cli-test:native .
docker build --target test -f memory_platform/Dockerfile -t kairos-memory-tests .
docker build --target lifecycle-test -f memory_platform/Dockerfile -t kairos-lifecycle-tests .
python scripts/build-handbook.py
```

Los builds no arrancan ni reinician servicios existentes. El target de ciclo de vida posee su PostgreSQL temporal y crea únicamente datos sintéticos. La pérdida de respuesta se reproduce después de una aceptación remota real; tras recarga existe un único evento con el mismo hash, UUID y etiquetas. La sonda corregida activa embeddings y mide las llamadas a un proveedor controlado: una para la nota manual de control y cero adicionales para el evento técnico. Las pruebas de generación del servidor se mantienen separadas.

La instalación npx offline prueba ambos modos: conexión básica y hooks opcionales, convergencia, runtime estable y ausencia de credenciales reales. Una instalación correcta no sustituye la ejecución y confianza dentro de cada cliente. Referencias: [manual de instalación](../../install.md), [contrato consumidor](../../integration.md) y [evidencia](testing/verification.json).
